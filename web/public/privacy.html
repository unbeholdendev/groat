Privacy and data flows

Groat stores a shared ledger on the server running this instance. Configured AI services and exchange-rate services receive some data. Ask the server operator which endpoints they use and how they protect the server, its logs and backups. Self-hosting alone does not keep AI requests local.

Member access

Separate sign-ins use the same dataset. Every signed-in member can read, add, edit, bin, restore and permanently delete other members’ expenses, see receipt attachments, manage shared categories and recurring entries, and export the ledger as CSV. Chats and their saved messages are also shared: members can read, continue and delete each other’s chats. The name shown on an expense records who added it; it does not restrict access.

Admins can add or remove members, reset their passwords and download a database backup. Removing a member revokes their sessions and capture tokens but keeps their expenses. Each user manages their own capture tokens. A capture token can submit entries to the shared ledger; it cannot read the ledger through the normal expense API.

AI requests

AI is enabled only when the operator sets AI_BASE_URL, AI_API_KEY and AI_MODEL. Requests go from the browser to the Groat server, then from the server to the configured endpoint. The API key is sent by the server as a bearer credential. The endpoint may be a hosted provider or a locally hosted compatible model. A local endpoint keeps these requests local only if that service and its infrastructure do so. Groat provides no on-device AI or end-to-end encryption guarantee; the server and the receiving service can read request contents. Transport protection depends on the configured URLs and hosting setup.

Retention, logging, use for training, deletion and any charges depend on the provider, account terms and operator configuration. Groat cannot promise that a provider discards requests. Hosted AI and speech services may charge separately, including for repeated requests and chat tool rounds.

Text capture and receipts

When AI is enabled, submitting an unclear quick-add line sends the submitted text to AI_BASE_URL/chat/completions with AI_MODEL. Confidently parsed lines and saves through the full form skip AI. Draft requests include today’s date, recent currencies, and expense-category IDs, names and parent IDs. Text may include notes, amounts, dates and tags. Drafts are shown for review before saving.

Token capture at /api/capture also uses AI for uncertain text when configured. It saves AI results as pending entries for review. Confident entries skip AI; failed AI extraction falls back to the built-in parser.

Selecting, pasting, dropping or sharing a receipt photo starts extraction. The browser converts it to JPEG, with a longest edge of at most 1,600 pixels, and uploads it to Groat. The server sends the image as a base64 data URL to the same chat-completions endpoint, with the same date, currency and category context. It uses AI_VISION_MODEL if set, otherwise AI_MODEL. The image can reveal everything visible on the receipt, beyond the fields extracted into the expense. A successful extraction stores the uploaded image on the server even before you save the draft.

Voice

Dictation requires AI plus AI_STT_MODEL. After recording, the browser uploads the audio to Groat. The server sends the recording and model name to AI_STT_BASE_URL/audio/transcriptions, using AI_STT_KEY. If either setting is absent, its base URL or key falls back to the corresponding main AI setting. The transcript then goes to the main chat-completions endpoint for expense extraction, with the text context described above. Two services may therefore receive parts of a voice entry. Groat does not save raw recordings or transcripts as separate database records; extracted expense fields are saved when you accept the draft.

Questions and tool results

Submitting a question with ? or in a chat sends it to the main chat-completions endpoint. Each request includes the saved history of that chat, previous tool calls and results, today’s date, base currency, all category IDs, names, parent IDs and expense/income kinds, and tool definitions containing the database table schema.

The model can request expense lists, category totals, period comparisons, expense drafts and read-only SQL queries. Groat runs these on the server and sends the results back in subsequent requests. Results can include notes, amounts, currencies, dates, tags, categories, attribution and converted amounts. Lists and SQL results are limited to 200 rows per call; one question can cause several calls.

The SQL tool can query the whole database, including pending and binned entries, chats, receipt bytes, user records with password hashes, sessions and hashed capture tokens. Its read-only restriction prevents writes, but does not restrict which tables it reads. Do not assume that a spending question exposes only spending totals. Groat saves the conversation, including tool calls and results, in the shared database. Deleting a chat removes its saved messages from Groat, but does not retract requests already sent to a provider.

Browser storage and sign-out

The browser persists fetched app data and drafts in localStorage, alongside queued or failed offline changes. This can include expenses, categories, settings, session identity and fetched chats. It lets a previously loaded app show cached data offline. Queued entries are device-local until the server accepts them; closing the tab is not proof that they were saved on the server. Browser storage can fail or be cleared. Keep the tab open and reconnect if Groat reports a storage failure.

Queued changes retain the original username. They resume when connectivity returns and require that account to sync. Interrupted changes may need a manual retry. A saved queue prevents a different account from signing in until the original user syncs it or the unsent changes are cleared. AI extraction, receipt reading and dictation require a connection.

Sign-out waits for active changes and asks before discarding unsent changes. It removes Groat’s localStorage data cache, queued changes and in-memory app data, then marks the device signed out. It attempts server logout; if offline or unreachable, server-session invalidation is delayed until a later successful logout request. Sign-out does not delete server records, downloaded exports or backups, browser history, or other tabs’ already loaded data.

The service worker separately caches the app shell and same-origin pages and assets, excluding API requests. A shared image is held in a separate browser cache until the app consumes it. Sign-out does not clear these service-worker caches or the theme preference. Clear this site’s browser data to remove remaining local storage, including an unconsumed shared image. Groat does not encrypt its browser cache.

Server storage and rate lookups

The server uses SQLite at DB_PATH (default data.db; the Docker image uses /data/expenses.db). It holds expenses, tags, categories, recurring schedules, settings, exchange rates, receipt image bytes, chats, user records, sessions and capture-token metadata. Passwords and capture tokens are hashed. Groat does not add database encryption; access to the server, database files and backups remains an operator responsibility.

Binning keeps an expense and its attachment until permanently deleted. Unattached receipt images older than 24 hours are cleaned up on a later successful photo extraction, rather than by a timed job. The app’s downloadable backup includes account password hashes and photos, but excludes sessions, capture tokens and chats. A raw database copy can include all of them. Deletion does not remove older copies held in backups or provider systems.

Converting foreign-currency expenses for lists, totals, exports or AI tools can trigger server-side rate requests, even with AI disabled. Fiat rates come from api.frankfurter.dev/v2/rates, with the expense date, USD base and required currency codes. Bitcoin rates come from mempool.space/api/v1/historical-price, with USD and the date’s end-of-day timestamp; api.coinbase.com/v2/prices/BTC-USD/spot with the date is the fallback.

These rate requests send dates and currencies, rather than expense notes, amounts, account names, receipts or audio. The services also see the server’s network address. Groat caches historical rates in SQLite and keeps current-day rates briefly in memory to reduce requests. Same-currency entries need no conversion request; unavailable rates leave converted amounts unknown.

Using Groat without AI

Leave the AI settings unset to use quick-add parsing, the full expense form, editing, categories, tags, recurring entries, token capture, exports and spending summaries without an AI provider. Unclear text can be completed in the form; uncertain token captures remain pending for review. Asking questions, AI text extraction, receipt reading and dictation require configured AI. Core expense capture does not require an AI subscription. Foreign-currency conversion can still contact the rate services described above.
